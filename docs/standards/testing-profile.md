# AI-TTS testing profile

The portable [Testing Standards](testing.md) are binding. This profile records
the local risk map, budgets, enforcement, and known blind spots. It narrows the
standard to this repository; it does not weaken it.

## Change declaration

Every commit and pull request declares exactly one kind:

- `refactor`: behavior and tests do not change;
- `feature`: new behavior and new boundary tests;
- `bug fix`: a regression test is observed red on the unfixed parent;
- `behavior change`: an existing expectation changes deliberately.

Commit bodies use `Change-kind: <kind>`. Pull requests carry the same field.

## Enforced Python test classes and budgets

| Class | Ceiling per test | Resource posture |
|---|---:|---|
| small | 2 seconds | one process; no filesystem, sockets, threads, or sleeps |
| medium | 15 seconds | one machine; owned filesystem, Unix sockets, subprocesses, or threads allowed |
| large | 30 seconds | explicit external boundary; none currently gate CI |

The complete Python suite has a 30-second budget. `tests/conftest.py` rejects
collection unless each test inherits exactly one size marker and one non-empty
`oracle(...)` marker, then installs the class timeout. The policy and timeout
gates have falsification receipts in
`docs/testing-evidence/2026-09-03-policy-gates.md`.

The Swift XCTest suite is medium. Each test gets a 15-second XCTest execution
allowance, its source file carries harvested size/oracle declarations, and CI
runs the complete Swift suite behind a 60-second process-group deadline using
`scripts/run_with_deadline.py`.

CI does not retry failed tests. Coverage percentages and mutation scores are
not gates. New load-bearing assertions need a falsification record; bug fixes
need red-on-parent evidence or the written irreproducible-failure carve-out.

## Initial risk map

| Subsystem | Highest-consequence claim | Contract boundary and oracle | CI evidence | Accepted blind spot / next instrument |
|---|---|---|---|---|
| Public speech API | paused playback still accepts and spools speech | `SpeechServicePort`; approved product behavior | generated schema round trips; fake and real socket contract suites | publish versioned schema compatibility policy before 1.0 |
| MCP adapter | stdout is only JSONL; tool schemas remain machine-usable | MCP tool discovery/call plus raw stdio; MCP 2026-07-28 spec | in-memory SDK client and raw subprocess framing | no cross-SDK conformance matrix yet |
| Daemon IPC | malformed input fails typed and never masquerades as success | user-only Unix socket; architecture §5 | examples for malformed JSON, size, and typed errors | add coverage-guided or generated byte-stream parser campaign |
| Store and recovery | queued text survives restart without accidental speech | SQLite-backed store; architecture §§3 and 6 | reopen and restart recovery examples | add seeded write/crash fault matrix, including recovery-time faults |
| Playback | exactly one owner; FIFO/priority plan; hold survives controls | `PlaybackController`; architecture §§2 and 7 | deterministic fake sink and explicit race regressions | replace hand-picked races with seeded scheduler exploration |
| Synthesis and cache | failures isolate; ready audio is usable; disk remains bounded | synthesis pool/cache ports; architecture §§2, 4, and 6 | generated LRU model, real filesystem contract, seeded unlink failure | add fault injection for synthesis writes and full disk |
| Menu-bar app | one truthful unified Queue/History and global hold | Swift client model plus daemon snapshot; UI design | Swift model/client tests | UI automation and accessibility journey absent |
| Kokoro lifecycle | production engine starts and stops without wedging | engine adapter/process lifecycle | bounded non-cooperative shutdown process test; manual live acceptance | add automated real-Kokoro synthesis and teardown acceptance |
| Distribution | installed binaries and app do not depend on a checkout | wheel/app/launch artifacts | isolated wheel install, bundle/plist contracts, signed bundle CI build | add clean external-machine install and launch lifecycle acceptance |

## Adoption ledger

Enforced now:

- named oracle and explicit size class on every collected Python test;
- per-class time ceilings and a whole-suite latency budget;
- deterministic generated round trips for new public schemas and encoding;
- raw JSONL framing and no-stdout-noise check for the MCP server;
- recorded behavior-specific assertion calibration;
- no retry-to-green in local or hosted test commands.
- harvested Swift size/oracle declarations, per-test allowance, and a hard
  suite deadline.
- a configurable 1 GiB-default LRU cache cap, generated policy reference model,
  terminal-only filesystem contract, and seeded unlink-failure check.
- bounded process shutdown when a native engine call ignores cancellation;
- an OS-backed single-instance contract for the menu-bar process;
- installable wheel, standalone app-bundle, and shell-free launch-agent
  contracts, with real release-bundle construction in CI.

Still open for v0.1.0 readiness where the product makes the corresponding
promise:

- generated/fuzzed daemon NDJSON parsing with a permanent regression corpus;
- seeded store and synthesis-write fault injection for persistence and recovery
  claims;
- systematic playback interleaving exploration beyond named regressions;
- real-Kokoro synthesis/teardown and clean external-machine launch acceptance;
- final cross-language release matrix on the published commit.

Review this profile whenever a new trust boundary or durability promise is
introduced, and at least once before each release.
