# PR 26 Code Lawyer audit

Change-kind: bug fix

All checks run in the isolated audit worktree. New regressions inherit or carry
explicit size/oracle markers and use owned fixtures. Remove them when their
contract is removed or a stronger check subsumes the same failure.

## 1. Rejected submissions preserve voice claims

Boundary: daemon submission and voice-assignment operations. Oracle: a refused
submission cannot update the caller's saved voice. Medium, isolated store,
fake engine/sink. Parameterized invalid speed, invalid content format, and
Markdown with no speakable content each failed on the unfixed implementation:
the saved assignment changed from `af_heart` to `im_nicola`.

Move voice resolution after all submission validation. The same three cases
pass; the full voice-assignment and IPC suites pass (84 tests). This red run
also falsifies the unchanged-assignment assertion; no clock value is assumed.

## 2. Exports own their artifacts until completion

Medium daemon-boundary schedules gate the actual archive worker with events.
On the unfixed parent, storage deletion (including cancellation of the request),
cache purge, cache-cap enforcement, and history-plus-files clearing all fail the
file-preservation assertion. The worker now owns a per-task set of artifact IDs
and audio paths; cache eviction and generated-file deletion consult those pins.
A shield prevents client cancellation from ending filesystem ownership early.
Pins are released by worker completion, and shutdown drains those workers.

The five schedules pass, including exact audio bytes in the completed archive
and subsequent successful deletion. Mutating archived bytes to `wrong` fails the
archive assertion in all five cases. Incrementing the deletion receipt count
fails its exact receipt assertion in all five cases. Mutations were restored.
The export/cache/storage/IPC suites pass (56 tests), plus Ruff and mypy.
Retention uses the same protected artifact set; its existing selection contract
remains covered by the generated-storage suite.

## 3. Export provenance runs off the event loop

The medium export-boundary test records thread identity at the metadata-read
port while retaining real metadata reads. Before correction all four reads ran
on the event-loop thread, failing the worker-thread assertion. Move provenance
construction into the shielded export worker, keeping Store serialization on
the event loop. The same test passes. Replacing provenance construction with
an empty object fails the non-vacuity assertion (`export must read provenance
metadata`), so an export that reads nothing cannot pass. Mutation restored;
all 12 export/evidence checks and lint/type checks pass. No timing threshold is
used as a performance oracle.

## 4. Evidence reads do not create storage

Two medium filesystem-boundary regressions observe that an absent cache root
remains absent after metadata lookup and legacy export. Both failed red because
the original read paths created the root and artifact directory; both pass with
a non-creating identity resolver. Write paths still create private directories,
and the resolver refuses symlink roots/artifact directories. All 14 evidence
and export lifecycle tests pass, with Ruff/format/mypy clean.

## 5. Missing generated-cache roots are empty inventories

The small owned-filesystem regression calls the inventory boundary with a
nonexistent cache. On the unfixed code it raises FileNotFoundError instead of
returning the specified empty list. Catch that absence at root enumeration and
return no entries; do not create storage as a side effect of an inventory read.
The regression and storage/export suites pass (9 tests), as do lint and mypy.

## 6. Literal arithmetic and inline code survive speech cleanup

Two small projection-boundary cases failed on the unfixed code: `2 * 3 * 4`
became `2 3 4`, and inline code `* literal *` lost its stars. Only prose runs
now receive loose-star cleanup; inline code terminates a prose run and is copied
literally. Loose-star spans without alphabetic content are retained, preserving
numeric multiplication. Both regressions and the full segmentation suite pass
(9 tests), with lint/format/mypy clean. This remains a forgiving prose heuristic;
explicit plain-text submissions bypass Markdown interpretation entirely.

## 7. Multiline loose emphasis

A small Markdown projection case with YAML front matter and a two-line loose
star span failed on the parent: `** first\nsecond **` remained in the output.
Allow line breaks inside the prose span; the regression now yields
`first\nsecond`, preserving its text and line break. All 10 segmentation checks
pass, including numeric arithmetic and inline-code preservation. Lint and type
checks pass. The failing parent output calibrates the exact projection assertion.

## 8. Punctuation terminates loose emphasis

Two small boundary cases failed on the parent: adjacent punctuation preserved
raw stars; spaced punctuation retained an unwanted gap. Recognize punctuation
as a closing boundary and consume only a gap between closing stars and that
punctuation. Both yield `spaced.`. All 12 segmentation tests and lint/type checks
pass. The parent failures calibrate both rows of the exact projection oracle.

## 10. Reload regression waits for the state it tests

A controlled authoring-time pytest plugin replaced FakeEngine.warmup with a
threading.Event wait and wrapped Daemon._op_snapshot to set that event only
*after* constructing its first snapshot. Thus the first snapshot deterministically
reports loading; no elapsed-time assumption decides the interleaving. On the
unmodified reload test this fails `loading == failed`: restart was refused before
the injected restart failure ran. The test now polls snapshot readiness before
restart and requires the `internal` error. With the same startup schedule it
passes, and all 48 IPC tests pass without the plugin.

Temporarily changing the reload-error response from INTERNAL to ILLEGAL_STATE
fails the new exact error-type assertion, then restoring it passes. This is a
test bug fix; production behavior is unchanged. Size remains medium, using the
existing isolated daemon and IPC oracle. Lint, format, and mypy pass.

## 11. Give storage maintenance the long transport allowance

Change-kind: bug fix. The Swift medium socket-boundary regression seeds an
owned socket pair with a complete response, sends actual `DaemonClient` requests,
and reads `SO_RCVTIMEO` from a duplicate of the client descriptor. The connector
seam transfers descriptor ownership without replacing request or timeout code.
Oracle: storage inventory/deletion and clear-with-files receive 120 seconds;
ordinary controls retain 10 seconds. No elapsed-time inference or sleeps.

Red on the unfixed timeout policy: both storage cases and clear-with-files
reported 10 rather than 120 seconds. Green after adding those operations.
Calibration: broadening the long allowance to ordinary clear/snapshot requests
fails the short-timeout cases; introducing a 100,000-microsecond fraction fails
the exact timeout assertion. Both mutations were reverted. This checks transport
configuration, not completion of arbitrarily large filesystem work in 120 seconds.

## 12. Bring the XCTest invocation mitigation forward

Change-kind: bug fix. PR #26's full warnings-as-errors Swift run on `13086c9`
crashed with signal 11 entering the caption-preference test. The owned crash
report (`xctest-2026-09-30-044523.ips`) identifies the same task-local/XCTest async
invocation path tracked by issue #6. Imported the isolated test-only change from
PR #32 (`5674ed8`), retaining its attribution and upstream investigation receipt.
With synchronous bounded XCTest waits, all 106 tests pass. Suppressing the five
completion signals again made the six waits fail on unfulfilled expectations;
the mutation was reverted. No failed run was retried unchanged into green.
