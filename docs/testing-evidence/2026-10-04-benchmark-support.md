# Source-pinned benchmark support

Change-kind: bug fix. Issue #68. Oracle: a controller benchmark must execute and identify the selected source's playback helpers, and the paired comparator must refuse modified reference support.

## Change

`DeterministicPlaybackSchedule`, `make_composite_ready`, and `settle` move unchanged into `tests/support/playback.py`. Tests import that shared module. Benchmark cases and failure probes load it from the checkout containing the selected `aitts` package. The unchanged pinned reference `0290f3cf3a0c3930256f42f31500bda59c1eabeb` predates this layout, so the loader selects its own `tests/test_playback.py` and `tests/conftest.py`. An already-loaded test package from another checkout is refused rather than reused. The candidate's benchmark harness remains common to both arms; helper versions intentionally follow their measured application.

Reports retain candidate harness hashes and add `environment.playback_support_sha256` for the selected checkout's package and helper modules. The MLX boundary does not claim to use playback helpers. Reference admission now checks `tests` as well as `src`, including ignored importable code, links, and opaque directories under either tree. Normal tagged bytecode caches remain allowed. Source-root execution is not a sandbox; it executes the selected checkout's code.

## Campaign descendant cleanup

The second independent review found a failure-path defect in the retained runner, not the benchmark helper loader: a child-command timeout could terminate the campaign leader before the outer guard cleaned up its descendants. The guard now attempts to terminate its owned process group on every exit, even after the leader has exited, and tolerates an already-absent group. This does not change the successful calibration results recorded above.

The medium, Linux-only process probe in `cleanup/probe.txt` replaces only the campaign workload with an owned child that starts a sleeping descendant and then times out. It preserves the actual outer guard. With the runner from `38055c7`, `cleanup/red.json` observes the descendant still sleeping (`S`) after guard completion and the probe fails its no-running-descendant assertion. With the corrected runner, `cleanup/green.json` observes the terminated descendant (`Z`), then explicitly reaps it using the probe's own subreaper boundary. Both guard invocations return one for the injected timeout; GREEN refers to the cleanup oracle, not a successful campaign. The probe's `finally` block kills and reaps its owned descendant even after RED. Both sampled resource records are retained. The fixture starts one descendant, writes a PID and bounded logs, and imposes a ten-second outer deadline; it does not exercise physical power loss or every resource-refusal condition. Delete this probe when the retained runner is retired or a shared guarded runner supplies stronger equivalent coverage.
