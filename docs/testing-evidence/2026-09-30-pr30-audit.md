## 5. Screen fitting must not write a user preference

Change-kind: bug fix.
The medium sizing regression replays the original opening sequence: set the
available maximum and resize to current height. On `8403415` it failed four
assertions: opening a fresh card wrote 500 as a preference; fitting to 700
replaced the chosen 1500; returning to 1800 retained 700; reconstruction also

boundary. `StatusController` uses it both before constructing native content

The model keeps preferred and effective heights separately. Only an explicit
resize writes defaults. A display shorter than the normal 360-point minimum
can show a smaller effective height; its explicit choice persists 360 so a
later ordinary display honors the minimum rather than resetting to 500.
A seeded `preferredHeight = height` fault fails that short-screen reconstruction
assertion (500 versus 360), then is restored. All eight sizing/control/wiring
tests pass. Delete when persisted menu sizing or screen fitting is removed.
