# Zed document-reading task evidence

Change-kind: feature.

The contract is in [the Zed client README](../../clients/zed/README.md).
All new tests are medium: owned filesystem and Unix sockets, with an isolated
paused daemon, FakeEngine, and FakeSink. They do not use the listener's queue
or audio devices. Delete these assertions only when the Zed entry point is
removed or its stated admission contract changes.

## Falsification

The initial helper returned 1 without submission. All twelve initial cases
failed by assertion rather than import or fixture errors. Selection/file
admission failed on the exit code; refusals failed on absent error feedback;
daemon unreachability failed on its exit code. A fixture initially referenced
an incorrect status field; it was corrected against the existing socket
contract before the passing run.

Nine temporary production mutations were then applied one at a time and
restored in a finally block. Each final control produced pytest exit 1:

| Mutated behavior | Observed failing contract |
|---|---|
| Source changed to `wrong` | Selection attribution |
| Sensitivity changed to public | Selection confidentiality |
| Selection interpreted as Markdown | Exact literal selection preservation |
| File Markdown inference disabled | Spoken Markdown projection |
| Text ceiling reduced by one byte | Inclusive 512 KiB file admission |
| Encoded request ceiling removed | Local encoded-limit diagnostic |
| NUL refusal removed | Binary input must not enter the queue |
| Resume sent after submission | Existing playback hold survives |
| Binary input queued before reporting a pretend refusal | Snapshot plan must remain empty |

The first encoded-limit mutation survived because the daemon's own refusal
also produced exit 1 with no queue item. The test was strengthened to require
the local encoded-limit diagnostic; the repeated control then failed. This
distinguishes local validation from a downstream refusal.

The initial refusal assertion inspected terminal history, which cannot prove
the absence of queued items. It now inspects both the full snapshot plan and
history. The ninth mutation admitted binary text, returned exit 1, emitted an
error, and suppressed success output. The refusal test failed specifically on
the nonempty plan, independently of exit status and diagnostics.

The focused Zed, existing CLI, and existing client suite passed 49 tests before
host acceptance. Ruff and mypy passed for the changed Python code.

## Installed host acceptance

Zed 1.23.3 at `/Applications/Zed.app` was exercised with global tasks and an
owned workspace under `/tmp/ai-tts-zed-host`. Its tasks targeted a separate
paused FakeEngine daemon. No real playback was requested.

The first unfiltered task invocation from an untitled buffer received no
selection and displayed an error. Explicit environment mappings now require
the relevant Zed context. A saved file outside the window's worktree also
lacked task context. Opening its parent folder as a project supplied both
variables; this limitation is documented rather than claiming every buffer
is supported.

- Both named tasks appeared in the task picker inside the owned workspace.
- The selection task queued exactly `Zed AI-TTS selection acceptance.\n` with
  `zed:selection`, confidential sensitivity, Normal priority, and Ready state.
- The document task saved a dirty Markdown buffer before admission. Disk and
  queue text both became `# Zed changed heading\n\nSaved by the reading task.\n`.
  The queued parent had `zed:file` and a composite Markdown segment.
- The test daemon remained paused. Actual synthesis/audio quality and acoustic
  output are delegated to the existing daemon; this integration does not
  claim to have verified them.

## Final checkpoint

- Stopping the owned test daemon made the document task leave its terminal
  visible with `AI-TTS daemon is unavailable. Start AI-TTS, then run this task
  again.` Editor focus and text survived.
- After restarting the test daemon, a new selection task queued exactly
  `Second selection is current.` from a changed, unsaved buffer. The saved
  file remained the previous Markdown document, proving that selection
  admission did not save the buffer or reuse the previous selection.
- Global configuration at `/Users/james/.config/zed/tasks.json` was restored
  to the normal daemon by removing the temporary socket override. It retains
  the explicit Zed variable mappings and uses the absolute helper path in
  `/Users/james/git/ai-tts-zed-tasks/.venv/bin`. Existing keybindings were not
  edited. The owned test daemon was stopped.
- Repository-wide ruff, formatting, and strict mypy passed. The required
  pre-push suite passed 1,107 tests with two skips; its required Swift build
  passed. Optional keyboard bindings and real acoustic output were not tested.

The final queue-refusal assertion was strengthened after this full-suite run;
the focused suite and required push hooks are rerun for its published commit.
