# PR 27 Code Lawyer audit

Change-kind: bug fix

## 1. Integrate with the current Store API

The merge of main exposed an obsolete `Store.pending_queue` call. Mypy reported
the missing attribute, and the existing medium nested-preemption regression
failed to reach its first planning cycle; the playback task failed with the
same AttributeError. Use the public, ordered `playback_queue` inventory, filtering
Ready preempts as before. Ready records are the intersection of both inventories,
so no synthesis or priority policy changes. The preemption, voice-assignment and
maintenance suites pass, along with Ruff/format/mypy. This correction is recorded
in the integration commit, with the submission conflict resolved to preserve both
preempt validation and post-validation voice assignment.

## 2. Older ready alerts respect the current queue head

Medium controlled planning schedule: two preempt alerts are Ready before the
controller starts. On the parent, its next planning turn interrupts the newer
head with the older alert, failing the exact current-ID/device-start sequence.
Filter candidates to those ranked ahead of the nonterminal current item. The
regression now preserves the newer alert uninterrupted and starts the older one
at zero after natural completion; all nine preemption tests pass. Setting saved
starts to 42 ms separately fails the continuation-offset assertion. Mutation
restored. Oracle: queue rank controls takeover, and waiting alerts still play.
Retire with the preemption contract or stronger schedule coverage.

## 3. Recovery ordering does not depend on wall-clock behavior

Two medium seeded-clock recovery schedules persist three nested paused clips
through the Store boundary, recover, then Resume/Skip through the playback
controller. With equal timestamps, the parent resumes before the intermediate
alert; with decreasing timestamps, the oldest parent is adopted as current.
Both exact sequence assertions fail on the unfixed code. Accepted takeovers now
require a lower order_key; that durable rank reconstructs the active clip and
stack without a wall-clock ordering assumption. Both schedules pass, along with
all 38 playback/preemption tests. Resetting restored single-clip offsets to zero
fails the saved-offset components of both recovery sequences; mutation restored.
Oracle: nested resumption order and source positions survive clock ties/rollback.

## 4. Native preempt priority survives decoding, display, and requeue

The medium Swift adapter regression decodes a preempt History item and sends its
priority back through the actual typed-to-wire adapter. Before the fix, both its
priority and outgoing request said normal. Add the missing enum case, a distinct
badge/action description, and the corresponding requeue menu choice; Queue and
History render the item's actual priority. All 108 Swift tests pass with warnings
as errors. Replacing the preempt badge with Urgent and separately replacing its
action description with queue-only wording fails the exact presentation oracles.
Those mutations were restored. Native menu clicks remain a manual UI blind spot.

## 5. Suspended speech remains visible in the upcoming queue

The medium native snapshot-boundary regression covers both a playing and held
current alert, with suspended speech behind it. Both cases originally omitted
the suspended ID. Include noncurrent Paused items in `upcoming`; the existing
Clear Queue availability therefore sees them. Keep the active paused clip out
of the list. While a suspended stack exists, disable reordering at presentation
and action boundaries; its individual Cancel control is also disabled because
the daemon's supported operation is Clear Queue.

Exact upcoming-ID assertions now pass. Mutations forcing reorder eligibility
always true/false fail the respective availability assertions; removing current-ID
exclusion fails both the stack and subsequent ordinary-queue assertions for a
held current clip. All mutations restored. View rendering/clicking remains an
explicit manual acceptance gap; tests verify the presentation state contract.

## 6. Correct the design decision summary

Documentation-only bug fix. The summary's Ordering and Priority bullets said no
clip could interrupt current speech and barge-in was unimplemented; its Views
bullet omitted suspended speech. Compared those claims directly with the new
architecture section and controlled preemption/native projection receipts, then
updated the summary to distinguish ordinary Urgent ordering from explicit Ready
preemption, LIFO resumption, authoritative holds, suspended Queue entries and
nonzero synthesis/device latency. No artificial text-matching gate was added;
these are corrected explanations of already-tested behavior.

## 7. Count underflows reported by the stop fade

The medium PCM/evidence-boundary regression controls a stream that reports an
underflow only for the final fade block. On the parent, playback evidence contains
only `stream_closing` with zero underflows; the exact expected underflow event and
count fail. Both source and fade writes now use the same bounded diagnostic
handling. All 38 audio-device/evidence/preemption tests pass, including the
existing truthful/bounded warnings and exact stop-envelope/source-position checks.
Ruff, formatting and mypy pass. The unfixed evidence calibrates both the missing
event and incorrect count. This remains a driver-report oracle, not acoustic
hardware acceptance. Retire with the stop fade or a stronger PCM-boundary check.

## 8. Emit committed segment suspension events

The medium Store subscriber-boundary regression suspends a playing document
chunk, then refreshes its paused offset. Before the fix, the expected segment
transition list is empty. Capture its prior state and emit Playing-to-Paused
through `on_segment_transition` after commit; a pure paused-offset refresh emits
no additional transition. A separately opened Store reads parent/child state
inside the callback, verifying that subscribers see committed state.

The regression and all 41 Store/preemption checks pass. Moving the callback ahead
of commit fails the independently read state components; emitting again on an
already-Paused chunk fails the exact one-event sequence. Both mutations restored.
Ruff, format and mypy pass. Retire when this notification contract is removed or
subsumed by stronger event/durability checks.
