# PR 29 audit evidence

Change-kind: bug fix.

## Provenance lifetime follows History

The local agy review identified that removed History items retained cached
provenance. The regression enters through `AppState.applySnapshot` and
`loadProvenance`, using the same asynchronous provenance-loading boundary as
the UI. Its explicit medium size and oracle are declared in the test source.
A controlled loader records completions, so the test itself chooses exactly
when a response arrives; it uses no sleeps, polling or background races.

With the loading boundary extracted but the original `51b2fd1` state behavior
unchanged, the regression observed three failures: removed cached details
survived, a pending response restored removed details, and empty History kept
both. Snapshot projection now retains only current History IDs; completion
checks that the requested clip remains in History before retaining its text.
The retained clip's details must survive pruning. The multi-step test is one
lifetime contract, with removal-before-completion explicitly controlled.

The owned AppKit control regression uses this loader boundary too. Its click
must register the correct ID, then the harness delivers the expected details.
The production loader retains the existing off-main socket call and explicit
main-actor delivery. A separate medium adapter test checks success, typed
failure messaging and actor isolation with XCTest completion events. Its
one-second timeout is a hang bound, not a synchronization delay.

Seeded faults, all observed red and restored before verification:

- Removing the late-response history check restores `pending` private details.
- Pruning every entry loses `kept` details at both lifetime assertions.
- An inert native button fails the requested-clip completion unwrap.
- A wrong exporter clip ID fails the exact delivered details assertion.
- Replacing the failure message fails the exact error result assertion.

The three provenance tests pass after restoration. The original red/green and
inert-action evidence remains scoped to its original commit in the earlier
receipt. Delete these tests only when the corresponding History action,
provenance cache or asynchronous loading boundary is removed.
