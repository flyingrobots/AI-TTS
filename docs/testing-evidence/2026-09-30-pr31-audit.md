## 1. Identify the composer's native origin

Change-kind: bug fix.
Medium regression at the daemon provenance boundary with an owned Store and
inert daemon. Plain `menubar-composer` and a file/clipboard-attributed source
both returned `Unknown (legacy clip)` instead of `User composed speech` on
`d1a373e`; caller attribution remained intact. The same missing source mapping
also affects current clips, whose fallback label is `Unknown`. The first test
setup tried submitting through an unstarted daemon and failed before the
assertion; that setup error is not red evidence. Seeding through the public
Store contract isolates the provenance behavior and produced the two intended
assertion failures. Adding the source mapping fixes both. The replay-precedence
matrix now includes a composer import source and must still report History replay.
Delete only when native provenance or composer sources are retired.

## 2. Observe composer completion through events

Change-kind: behavior change (test synchronization only).
The original helper polled a Date deadline and ran the main loop in 10 ms
slices. It now fulfills a named XCTest expectation after the owned async
operation completes, with a two-second hang bound. The test methods remain
synchronous, preserving the issue-6 invocation mitigation; every draft,
request, rejection, notice and busy-state assertion is unchanged.

Calibration: removing only `finished.fulfill()` produces five unfulfilled
`Composer operation completed` failures across the import/submit and rejection
exchanges. Restoring it returns both tests to green. No production change or
preexisting runtime-failure claim accompanies this helper correction. Delete
only when these async composer behaviors are retired.

## 3. Refresh the persistent composer's selection target

Change-kind: bug fix.
The local agy review found that direct composer-window reactivation bypasses
menu capture, leaving an old target, and that nil menu capture retained it.
The two medium regressions use an owned NotificationCenter and defaults suite.
The test process stands for an external application under an injected distinct
owner PID; no Accessibility read, real activation or workspace subscription
occurs. Before observer behavior and nil clearing were added, the tests observed
stale PID 42 instead of the new activation, and 42 instead of nil.

The composer window controller now owns a main-queue activation observer.
External activations update the target; self activation retains it; absent
application metadata clears it. Menu capture also assigns nil explicitly.
The observer is removed on controller destruction. StatusController allows an
owned notification center so its existing production-wiring test stays isolated.

A fixture initially read NSRunningApplication.current before initializing
NSApplication, yielding invalid PID -1. That setup was corrected explicitly;
those initial calibration attempts are discarded. With valid owned AppKit setup,
seeded faults detect accepting self activation, ignoring unknown activation,
and omitting observer cleanup, each at its exact target/lifetime assertion.
The known import-port test separately verifies that the target PID reaches the
selected-text reader. No hardware app-switch/Accessibility acceptance is claimed.
Delete only when selection import or the persistent composer is retired.

Delete only if interpretation selection or draft reset is removed.
