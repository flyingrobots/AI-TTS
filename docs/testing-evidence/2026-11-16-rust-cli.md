# Rust command-line client, part 1: verification record

Change kind: feature. On 2026-11-16 the `aitts-cli` crate was tested against
the acceptance criteria of
[issue #138](https://github.com/flyingrobots/AI-TTS/issues/138), for every
command except `wait` and `say --wait`. This record is agent-written and has
not received human editorial review.

## Contract

- Each command line gives the same request, or the same refusal and exit
  status, as the Python CLI.
- The client prints the daemon reply as JSON. Exit status 0 means the daemon
  accepted; 1 means a daemon error or a refused command line; 2 means the
  daemon is unreachable or the grammar refused an argument.
- The binary runs with no Python on the path.
- No argument list causes a panic.

Human-readable text (help, usage and error messages) is not part of the
contract and is not tested.

## Tests and oracles

| Test file | Size | Oracle |
|---|---|---|
| `tests/test_cli_parity_table.py` (85 rows) | small | The Python `aitts.cli.main` with `Client.request` replaced by a recorder. It keeps `tests/fixtures/cli_parity.json` equal to what the Python CLI does. |
| `crates/aitts-cli/tests/parity.rs` (2 tests) | medium | The same table. A recording socket peer answers every request with a `not_found` error. 59 rows must send exactly the table request, exit 1, and print the peer's error. 26 rows must exit with the table status and send nothing. |
| `crates/aitts-cli/tests/live.rs` (2 tests) | medium | The real `aitts-daemon` serving the Python-written `golden.db`. For `status`, `voices`, `settings`, `list input`, `list playback`, `history --limit 2`, `get utt_0001` and `get no-such-id`, the printed JSON must equal the daemon's reply to the same request on a raw socket, with exit 0 (1 for the missing id). An absent socket gives exit 2 and error type `unreachable`. |
| `crates/aitts-cli/tests/binary.rs` (2 tests) | medium | The built binary run with an empty environment (no `PATH`, so no Python): `AI_TTS_SOCKET` and then `AI_TTS_HOME/ai-tts.sock` choose the socket (`aitts.paths.default_socket`). |
| `crates/aitts-cli/tests/fuzz.rs` (1 property, 2048 cases) | small | Random command lines built from subcommands, option/value pairs (including `nan`, `inf`, `1e999`, `-1`) and arbitrary strings exit 0, 1 or 2 and never panic. The socket does not exist. |

Number comparison in the tests treats `2` and `2.0` as equal, because Python
writes floats with a decimal point and the contract is the parsed JSON.

## Observed RED

The tests were committed first (commit "test(cli): pin the Rust ai-tts client
to the Python CLI parity table") against a `todo!()` stub of `aitts_cli::run`.
All 8 Rust tests failed at the stub
(`cargo test -p aitts-cli --no-fail-fast`).

## Planted faults

Each fault was applied alone and then reverted.

| Fault | Failing test |
|---|---|
| `origin` sent as `cli` | `each_accepted_row_sends_the_python_request_and_reports_the_daemon_error` |
| Long-option prefixes refused | the same test (`--sens`, `--prio`, `--pre` rows) |
| `voice_languages` not split on commas | the same test |
| `assign-voice SOURCE VOICE --release` sent | `each_refused_row_exits_like_python_and_sends_nothing` |
| Grammar errors exit 3 | `each_refused_row_exits_like_python_and_sends_nothing` |
| A daemon error exits 0 | `each_command_prints_the_daemon_reply_and_its_exit_status` |
| Only `ok` printed from the reply | `each_command_prints_the_daemon_reply_and_its_exit_status` |
| Unreachable reported as `internal` | `no_daemon_exits_two_with_an_unreachable_error` |
| `AI_TTS_HOME` read before `AI_TTS_SOCKET` | both `binary.rs` tests |
| Socket file name `aitts.sock` | `ai_tts_home_chooses_the_socket_when_ai_tts_socket_is_unset` |
| A non-finite number panics | `random_argument_lists_exit_with_a_contract_status`, 5 of 5 runs |
| Python table row changed (`speed` -1.0 to -2.0) | `test_table_row_matches_python_cli[say hi --speed -1]` |

A first fuzz strategy found the panic in 1 of 3 runs. It was changed to weight
`say hi` and `settings` up; the record above is for the changed strategy.

## Repetition

All `aitts-cli` tests passed 10 times in a row (`cargo test -p aitts-cli`),
and once in release mode. Stable libtest has no shuffle option; each test owns
its temporary directory and socket and shares no state. pytest runs the table
in random order through `pytest-randomly`.

## Live Python daemon

Not in CI, because the Rust CI job has no Python environment. Run once by hand:
`tests/fixture_daemon.py` served an owned temporary home, and each of the 85
table rows was run with the Python CLI and then with the Rust binary. 69 rows
printed identical JSON with the same exit status. 14 rows had the same exit
status and the same JSON shape, with different utterance ids or timestamps
(each `say` makes a new utterance). 2 rows differed because the first run
changed daemon state: `model-setup kokoro` (the second call finds a setup in
progress) and `assign-voice agent --release` (the second call finds no
assignment). With the Rust binary run first, the same 2 rows differed the
other way. The script was not kept in the repository.

## Not verified

- `wait` and `say --wait`, and exit status 3. They are part 2 of #138.
- Text from standard input: the Python CLI takes text only as an argument, so
  there is nothing to match.
- The JSON key order and float formatting of the printed reply. The contract
  is the parsed JSON.
