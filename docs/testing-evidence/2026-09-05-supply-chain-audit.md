# Supply-chain audit evidence — 2026-09-05

Change kind: feature

Oracle: the supported optional runtime graph must be frozen, audited,
inventoried, non-empty, internally consistent, and retained without bundling
the runtime or treating package metadata as legal advice

## Boundary

The dedicated `supply-chain` CI job uses Python 3.12, the minimum supported
runtime, and installs the `kokoro` extra plus a separately locked audit-tool
group. It then produces:

- a hashed requirements export from `uv.lock`, excluding the local project and
  development-only test tools;
- a `pip-audit 2.10.1` JSON result using the PyPI advisory service with
  `--strict`, `--require-hashes`, and `--disable-pip`;
- a CycloneDX 1.5 SBOM generated by `uv 0.9.18`;
- a `pip-licenses 5.5.5` inventory from the installed all-extras environment;
- normalized summary and license reports cross-checked by
  `scripts/verify_supply_chain_evidence.py`; and
- exact tool-version files, all retained for 14 days under the workflow commit
  SHA.

The workflow retains package metadata only. It does not capture speech text,
history, file paths, cached audio, or machine/user identifiers.

## Feature falsification

The verifier API and workflow contract were introduced before implementation.
The focused run exited 1 with six expected failures: five verifier behaviors
raised `NotImplementedError`, and the workflow test could not find a
`supply-chain` job.

The verifier cases require a healthy non-empty report to normalize, and reject
an empty audit, a reported vulnerability, an audited dependency absent from
the SBOM, and an audited dependency absent from the license inventory. The
workflow contract requires all extras, runtime-only export, hashed pins,
strict collection, pip-disabled resolution, an explicit advisory service,
CycloneDX output, inclusion of system packages in license collection,
cross-report verification, always-run artifact upload, and 14-day retention.

## Probe-driven corrections

The first real `pip-audit` probe attempted its default dependency resolution.
Its temporary environment's `ensurepip` process aborted on both Python 3.13
and Python 3.12. The final design avoids that hidden environment entirely:
`uv` exports the already-resolved transitive graph with hashes, while
`pip-audit --disable-pip --require-hashes` audits those exact pins.

The first clean-environment reconciliation also failed closed because
`pip-licenses` omits `setuptools` by default while `pip-audit` includes it.
Adding `--with-system` made the inventories agree. License output uses the
bounded mixed classification instead of retaining complete embedded license
texts.

## Isolated end-to-end receipt

The exact workflow recipe ran against a fresh CPython 3.12 environment outside
the repository venv. It installed 124 runtime/audit distributions and produced
the following verified summary:

```json
{
  "dependency_count": 104,
  "license_record_count": 104,
  "sbom_component_count": 127,
  "unknown_license_count": 1,
  "unknown_licenses": ["espeakng-loader"],
  "vulnerability_count": 0
}
```

The SBOM count is larger because it preserves locked conditional components
for other platforms; the vulnerability and license reports cover dependencies
applicable to the supported macOS/Python 3.12 execution environment.

Package metadata also identifies `phonemizer-fork` as GPLv3+ and `num2words`
as LGPL. That is disclosure, not clearance. The source-only, non-vendoring
distribution boundary remains mandatory until a human review covers those
packages, `espeakng-loader`, the model weights, and voice assets.

## Assertion calibration

After the job was green, a temporary workflow mutant removed
`--require-hashes`, removed `--with-system`, and changed retention from 14 to
13 days. The workflow contract failed and listed exactly those three missing
requirements. The mutations were restored.

## Final verification

The restored exact tree passed:

- all 12 focused supply-chain/workflow contract tests;
- all 230 Python tests;
- all 71 Swift tests under the repository's 60-second deadline;
- Ruff lint and format checks, strict mypy, `uv lock --check`, and
  `git diff --check`;
- `actionlint` and `zizmor 1.28.0` (offline, one suppressed audit) with no
  reported workflow findings; and
- offline wheel/sdist construction, `check-wheel-contents`, and `twine check`.

The built wheel metadata contains only AI-TTS runtime requirements and the
optional `kokoro` extra. The audit-only dependency group does not leak into the
published package metadata.

## Remaining publication boundary

This is a local exact-tree receipt. GitHub currently has no branch ref on which
to execute the job, so a hosted exact-commit audit artifact remains a release
gate rather than an accomplished claim.
